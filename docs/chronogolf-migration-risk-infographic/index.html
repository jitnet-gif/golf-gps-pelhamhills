자체 티 시트가 Chronogolf 의 저작권을 건드리는 부분은 찾지 못했습니다. 저장소에 들어온 Chronogolf 코드·이미지·로고가 없고, 화면 흐름과 색값은 저작권 보호 대상이 아닙니다. 대신 성격이 다른 두 건 — 공개 저장소에 남은 실제 골퍼 이름, 그리고 데이터를 가져온 방식의 계약 확인 — 이 남아 있습니다.

왜 이렇게 봤는가

저장소 전체 검색(추적 파일 + 무시된 로컬 데이터), 공개 스냅샷 원문 파싱, 저장소 공개 설정 조회로 확인한 내용입니다. 세 항목의 무게는 같지 않습니다.

항목 1 / 3

저작권

낮음 — 진행에 걸림돌 아님

  • 추적되는 Chronogolf 소스·CSS·스크린샷·로고가 0건. 이미지 14개 중 해당 자산 없음.
  • 어드민 사이드바 워드마크는 자체 pelhamhills 마크. 타사 상표 미사용.
  • 스크린샷에서 뽑은 색값 자체는 저작물이 아님.
  • "행 = 티타임, 좌석 4칸, Rate 컬럼" 같은 업무 흐름은 보호 대상이 아님.
  • Next.js + FastAPI 로 독립 구현 — 코드 이식 흔적 없음.
항목 2 / 3

개인정보

실제 노출 확인 — 오늘 처리

  • 공개 저장소에 커밋된 기존 인포그래픽(HTML + PNG) 의 예시 화면에 실제 골퍼 이름이 들어가 있음 — 원본 export 와 대조해 예시 4건 중 3건(풀네임 1건, 실제 성 2건) 확인.
  • 성만 남아도 티타임과 묶이면 식별 가능 — 3건 전부 같은 위험으로 봐야 함.
  • PNG 에도 같은 이름이 찍혀 있음(이미지 확인 완료) — 텍스트 수정만으로는 부족, 이미지 재생성과 이력 정리까지 필요.
  • 반면 공개 티 시트 스냅샷은 정상 비식별화 — 이름은 Golfer 1~4, 이메일·전화·메모·감사로그 전부 비어 있음.
  • 실명·연락처 원본 파일은 git 무시 목록에 있어 저장소에 올라가지 않음.
  • 남는 잔여 위험은 스냅샷의 시간 + 요금제 조합 — 120명 규모에서는 추정 가능.
항목 3 / 3

이용약관

확인 필요 — 저작권이 아닌 계약 문제

  • 이관 스크립트가 출처를 관리자 화면 주소로 기록 — 화면에서 받아온 데이터임이 드러남.
  • BI 리포트도 스크립트 자동 수집 경로 — 자동 추출 제한 조항과 맞닿는 지점.
  • 예약·고객 데이터는 클럽 소유라 이관 자체의 명분은 충분.
  • 정리 방법은 하나 — Lightspeed 공식 export 요청. 메일 한 통으로 방식 논란이 사라짐.

남은 일 3가지

Step 01 · 오늘

공개 문서의 실명 제거

기존 인포그래픽의 예시 이름을 가상 이름으로 바꾸고 이미지를 다시 굽습니다. 이미 공개된 이력이라 git 이력 정리 여부도 함께 결정해야 합니다.

Step 02 · 이번 주

Lightspeed 공식 export

지원팀에 클럽 데이터 공식 추출을 요청합니다. 받으면 화면 기반 수집 경로는 폐기하고, 이관 스크립트의 출처 기록도 공식 파일로 교체합니다.

Step 03 · 정리

폴백 데이터 · 문구

오프라인 폴백용 스냅샷을 합성 데이터로 바꾸면 노출이 0 이 됩니다. 공개 저장소 주석의 "복제" 표현은 "참고한 배치" 정도로 순화합니다.

결론

Chronogolf 를 대체하는 자체 티 시트는 계속 진행해도 됩니다. 막아야 할 것은 프로그램이 아니라, 공개 저장소에 올라간 실명과 데이터를 가져온 방식입니다.

가장 급한 것

공개 문서의 실제 이름 3건. 저작권 논쟁보다 실제 사람의 이름이 공개 인터넷에 남아 있는 쪽이 먼저입니다. 나머지는 메일 한 통과 문구 정리로 끝납니다.

확인 범위 · 저장소 전체 파일 검색, 공개 스냅샷 원문 파싱, 저장소 공개 설정 조회. 법률 의견이 아니라 실무 위험도 정리이며, 계약 해석이 필요한 항목은 "확인 필요" 로 표시했습니다. 이 문서에는 실제 고객 이름·예약 시각·클럽 식별자를 넣지 않았습니다.
